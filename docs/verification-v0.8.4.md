# 截图晾衣架 0.8.4 验证说明

## 本次修改

图片预览与悬浮窗口保留 1 DIP 可见边框，新增四边、四角共八个透明指针区域。四边感应宽度 5 CSS px，四角 8×8 CSS px；悬停显示对应方向箭头，按住拖动改变窗口宽度与高度。置顶与关闭按钮向可见区域内缩 6 CSS px，留出右上角尺寸调整的位置。

边框调整使用主进程系统鼠标 DIP 坐标，保持未拖动的对边位置。图片在实际窗口客户区内按原比例居中完整显示，不拉伸、不裁切，窗口比例不同可以留空白。图片内部与空白处仍移动整个窗口；按钮正常响应。拖动与尺寸调整互斥，松开、失焦、取消捕获、关闭窗口及其他窗口控制操作会结束当前手势。

手动调整后移动窗口保留当前宽高；滚轮、缩放按钮、适应屏幕与 1:1 恢复按图片比例计算窗口。各图片窗口独立调整尺寸、移动和置顶。最小窗口为 64×48 DIP，图片倍率最高 1600%，实际窗口绘制面积不超过 1600 万像素、最长边不超过 8192 物理像素，按所在显示器比例换算。允许超屏，但保留至少 64×48 DIP 可操作的一角。

新增 IPC 仅允许已注册图片窗口的主 Frame 调整自身，不接受其他窗口或任意窗口 ID。指针请求按帧合并，复用已加载原图，不生成新的图片缓存，不新增常驻窗口、渲染进程或后台服务。

窗口交互与主进程尺寸控制参考 Electron 官方的 [自定义窗口交互](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions) 和 [BrowserWindow 接口](https://www.electronjs.org/docs/latest/api/browser-window)。

## 验证与记录

176 项逻辑测试全部通过，其中图片窗口控制与几何测试 32 项。源码与最终 ZIP 解压程序分别通过 33 组图片功能、18 组便签功能验收；便签相关全部窗口的页面错误为 0。最终包的 29 个程序源文件逐字节与当前源码一致，运行元信息及随包使用说明也一致。

真实 Windows user32 鼠标验证了图片内部拖动移动整个窗口、拖动右边只改变宽度、拖动右下角改变宽高；从置顶按钮按下后拖动鼠标不会移动窗口。八个热区均实际命中，游标方向正确，可见边框保持 1 CSS px。图片在自由框中完整居中，保持原比例；恢复适应屏幕后重新收紧窗口。

受控坐标验证了左上角缩至 64×48 时右下边保持、巨幅拉框受物理绘制上限约束、失焦与丢失捕获结束尺寸手势，多个图片窗的调整与置顶互不影响，衣架及便签无法操作图片窗口。跨 DPI 拖动上限与继续手势通过纯逻辑测试覆盖。

最终程序在强制 100% / 125% / 150% 渲染比例下检查了衣架宽度、图片窗口同步缩放、细边框与独立置顶。连续尺寸更新可能使原生窗口、页面视口、图片和按钮布局在不同帧到达；验收按最新状态与同次界面快照核对完整布局，等待同步后保留严格的边框、图片比例与滚轮锚点断言。

实际测试通过项、原生鼠标输入方式、窗口尺寸、显示条件及打包一致性，以交付 `verification` 目录中的记录为准。测试使用隔离数据和示例图片，不改写日常剪贴板，不向微信等外部程序发送测试图片。

真实鼠标验收只操作已校验句柄的隔离测试图片窗口。为排除其他软件遮挡，测试会临时置顶该窗口，完成后恢复此前状态；等待前后端均结束手势后再恢复光标。生产默认置顶行为保持不变。受控 DIP 坐标的边界分支与真实 user32 输入分别记录。

强制 100% / 125% / 150% 渲染比例的检查不会改变 Windows 系统缩放。不同 DPI 多显示器实际移动须具备对应设备后人工确认；纯逻辑覆盖不标记为实际多屏测试。

本版未重新进行内存对照测量；边框感应区不新增常驻进程，放大窗口的绘制缓冲可能随窗口面积增加。旧版程序、源码、交付包和用户数据继续保留。
